# ЕДИНОЕ ЯДРО «склейки» — одинаковое во ВСЕХ переодеваниях (галактика/аквариум/кухня…)

Это ТА ЖЕ механика, что в исходной Bubble Words. Меняется ТОЛЬКО обёртка (камера/форма/сеттинг),
правила склейки НЕ трогаются. Реализуй ровно это ядро, потом примени свой визуальный сеттинг.

## Контент
Слова и категории — из `SHARED.md` (массив CATS, копировать verbatim). Брать подмножество категорий под уровень.

## Правила ядра (инвариант — должны совпадать у всех)
1. Поле засеяно N категориями (старт: 4 категории × 4 слова = 16 объектов-слов), позиции перемешаны.
2. Каждый объект держит ОДНО слово. Игрок ТАЩИТ один объект на другой:
   - если оба ОДНОЙ категории → они СЛИВАЮТСЯ в одну растущую группу, которая копит слова этой категории; на группе видно прогресс `n/4`. Группы тоже можно сливать с одиночками/группами той же категории.
   - если РАЗНЫЕ категории → склейка не происходит, объект отщёлкивает назад, ход НЕ тратится (без штрафа).
3. Когда группа собрала ВСЕ слова своей категории (полная, n=4) → категория ЗАВЕРШЕНА: группа эффектно уходит с поля (по флейвору сеттинга) и освобождает место. Прогресс уровня +1.
4. ЛИМИТ ХОДОВ: каждая УДАЧНАЯ склейка = −1 ход (бюджет, напр. 16–18 ходов на 4 категории; минимум математически нужно 12 склеек). Счётчик ходов виден.
5. ПОБЕДА: все категории на поле завершены, поле очищено. ПОРАЖЕНИЕ: ходы кончились раньше.
6. UI обязателен: счётчик ходов, прогресс категорий (напр. `0/4`), на группах — `n/4`, тосты на завершение категории («Готово!» / флейвор), кнопка рестарта, экран победы/поражения, переход на следующий уровень (на 1 категорию больше).

## Жёсткие требования (как везде)
Single-file HTML, всё инлайн, vanilla JS, без CDN/сетей. Тач+мышь (pointer events). Портрет, помещается в 430×900 без скролла. Не падать в консоль.

## Что разрешено менять (обёртка)
Вид/камера, форма объекта, фон/арт, флейвор завершения категории, мелкий косметический твист (дрейф объектов, вращение поля, тикет-заказ) — НО он НЕ меняет правила 1–6.
